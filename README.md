# 🔐 DevVault

**Локальное хранилище инфраструктуры и данных доступа для разработчиков.**

DevVault — консольное приложение на TypeScript и Node.js, которое помогает хранить инфраструктурные данные проектов в одном месте: серверы, SSH-доступы, базы данных, домены, API-ключи и другую техническую информацию.

Вместо разрозненных заметок, файлов `.env` и записей в текстовых документах у каждого проекта есть собственная карточка со связанными ресурсами.

> Проект находится в разработке. Текущая версия уже поддерживает проекты, ресурсы, поиск, шифрование секретов и экспериментальный Agent для обнаружения данных доступа.

## ✨ Возможности

- **Проекты и ресурсы** — все данные инфраструктуры сгруппированы по проектам.
- **Поддержка разных типов ресурсов** — сайты, серверы, SSH, базы данных, API-ключи, Cloudflare, GitHub, Docker, DeployAdmin и заметки.
- **Несколько ресурсов на проект** — например, production-сервер, тестовый сервер и база данных в одной карточке проекта.
- **Поиск** — поиск по проектам и сохранённым ресурсам.
- **DevVault Agent** — обнаружение потенциальных данных доступа во вставленном тексте и файлах `.env`.
- **Подтверждение перед сохранением** — Agent предлагает сохранить, проигнорировать или отредактировать найденные данные.
- **Защита секретов** — пароли, токены и другие секретные поля шифруются.
- **Локальное хранение** — данные хранятся в локальной базе SQLite.

## 🛠️ Технологии

- TypeScript
- Node.js
- SQLite и `better-sqlite3`
- Argon2id — получение ключа шифрования из мастер-пароля
- AES-256-GCM — шифрование секретных данных
- Vitest — автоматические тесты

## 📦 Установка

### Требования

- Установленный Node.js и npm.
- Git — для клонирования репозитория.

### 1. Склонируйте репозиторий

```bash
git clone https://github.com/MaviK21/DevVault.git
cd DevVault
```

### 2. Установите зависимости

```bash
npm install
```

### 3. Запустите приложение

```bash
npm run dev
```

При первом запуске DevVault предложит создать новое хранилище и задать мастер-пароль.

**Важно:** запомните мастер-пароль. Он используется для доступа к хранилищу и не должен передаваться другим людям.

## 🚀 Как пользоваться

### 1. Создайте хранилище

При первом запуске выберите создание нового хранилища и задайте мастер-пароль.

После успешного создания хранилища появится главное меню.

### 2. Создайте проект

Откройте раздел **«Проекты»** и создайте проект, например:

```text
Karimoff
```

Проект может представлять сайт, приложение, серверную инфраструктуру или другой рабочий проект.

### 3. Добавьте ресурсы

Внутри проекта выберите **«Добавить ресурс»** и укажите его тип.

Поддерживаемые типы:

| Тип | Для чего нужен |
|---|---|
| Веб-сайт | Домен, протокол и заметки |
| Сервер | Хост, порт, имя пользователя и пароль |
| SSH | SSH-подключение и связанные ключи |
| База данных | Тип БД, адрес, порт, имя базы и учётные данные |
| API-ключ | Сервис и секретный ключ |
| Cloudflare | Аккаунт, домен и API-токен |
| GitHub | Репозиторий, имя пользователя и токен |
| Docker | Хост, реестр и данные доступа |
| DeployAdmin | Адрес и данные доступа |
| Заметка | Произвольная техническая информация |

Пример структуры проекта:

```text
Karimoff
├── Веб-сайт: karimoff.pro
├── SSH: production-server
├── База данных: PostgreSQL
├── API-ключ: Example Service
└── Заметка: информация о развёртывании
```

### 4. Просматривайте и редактируйте данные

В меню проекта доступны просмотр ресурсов, добавление, изменение, удаление и поиск.

Секретные поля по умолчанию отображаются в скрытом виде. Для просмотра необходимо отдельно подтвердить действие **«Показать секреты?»**.

### 5. Используйте поиск

Поиск помогает находить проекты и связанные ресурсы. Например, можно искать сохранённый IP-адрес или имя SSH-ресурса, чтобы открыть соответствующий проект.

## 🤖 DevVault Agent

Agent — экспериментальный компонент, который помогает находить потенциальные данные доступа.

На текущем этапе доступны два сценария:

1. **Сканирование вставленного текста.** Можно вставить команду SSH, строку подключения к БД или другой фрагмент текста.
2. **Сканирование файла `.env`.** Agent анализирует переменные окружения и ищет потенциальные учётные данные.

Для обнаруженных данных Agent показывает предполагаемый тип, контекст и уровень уверенности.

Дальше пользователь может:

- `Y` — сохранить;
- `N` — проигнорировать;
- `E` — изменить найденные данные.

При сохранении необходимо выбрать проект, к которому относится ресурс.

**Agent не сохраняет обнаруженные данные без подтверждения пользователя.** В текущей версии он работает с предоставленным текстом и указанными файлами, а не наблюдает за всеми терминалами в реальном времени.

## 🔒 Безопасность

Защита данных — один из основных принципов DevVault.

- Мастер-пароль не сохраняется в открытом виде.
- Для получения ключа шифрования используется Argon2id.
- Секретные значения шифруются с помощью AES-256-GCM.
- Ключ шифрования хранится в памяти во время работы с разблокированным хранилищем.
- Для просмотра секретов требуется отдельное подтверждение.
- Данные хранятся локально в SQLite.

### Важные рекомендации

- Используйте сильный мастер-пароль.
- Не добавляйте настоящие пароли, токены и приватные ключи в публичные репозитории.
- Не передавайте другим людям базу данных вместе с секретами.
- Не считайте шифрование заменой резервному копированию и защите компьютера.
- Перед использованием в критически важной инфраструктуре самостоятельно оцените модель угроз и ограничения текущей версии.
